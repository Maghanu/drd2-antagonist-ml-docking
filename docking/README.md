# DRD2 molecular docking

## Purpose

The docking workflow uses AutoDock Vina to generate poses and approximate
scores for candidate ligands in the human dopamine D2 receptor (DRD2). It is
used as a complementary prioritization step after pIC50 prediction. A docking
score is **not** an experimental binding affinity, and docking cannot establish
that a compound is an antagonist.

[`src/06_docking.ipynb`](../src/06_docking.ipynb) supports both a single ligand
and batch docking. Batch mode docks the 100 highest model-predicted pIC50
compounds from each of the scaffold-similarity and random ZINC22 collections.
Each set is run and reported separately so that rankings can be compared.
[`src/06_docking-comparisons.ipynb`](../src/06_docking-comparisons.ipynb)
docks every named SMILES in `data/raw/comparison_smiles` using the same
6CM4_Na receptor, box, and Vina settings as those two batches.

## Receptor and docking box

The receptor in `src/06_docking.ipynb` is read from the committed local file
`data/processed/crystal_structures/6CM4_Na.mmcif`; the notebook does not
download a structure. It retains DRD2 `ATOM` records at author residue numbers
35–222 and 364–442, excluding the T4 lysozyme fusion and unrelated records.
The processed CIF's single Na+ coordinate is included in the final Vina
receptor PDBQT. PDBFixer and restrained OpenMM minimization operate on the
protein atoms; the ion is added to the PDBQT after those steps because the
protein force-field preparation does not parameterize it.

The processed receptor CIF omits co-crystallized risperidone. The notebook
therefore reads the committed local raw file
`data/raw/crystal_structures/6cm4.mmcif` **only** to obtain component `8NU`
coordinates for the docking-box center. The box receives 8 Å padding in each
dimension. Both structure inputs are local; no structure download is needed.
The prepared receptor is cached under `docking/prepared/6CM4_Na/`, together
with copies of both CIF inputs.

The tracked `docking/prepared/6CM4/` cache and existing single-ligand run
files are historical outputs from the earlier no-sodium workflow. They are
not read or reused by the updated notebook; keep them as records of that
earlier run, and regenerate results before comparing them with the new receptor.

The report and Figure 4, the reference-control docking runs, and completed
rows in `docking/runs/docking_summary.csv` are not present in the repository,
so it is not possible to verify from the repository which receptor produced
Figure 4. If it was generated before this local-receptor workflow, rerun the
docking before attributing existing scores or figures to the Na+-containing
receptor. For analyses generated by this workflow, Methods should state that
the processed local 6CM4_Na receptor was used and that the raw local 6CM4 CIF
provided only the risperidone coordinates for the box.

## Environment and execution

The environment snapshot recorded on 2026-10-18 uses Python 3.12.15, Vina
1.2.7, Meeko 0.8.0, RDKit 2026.03.1, Biopython 1.88, PDBFixer 1.12, and
OpenMM 8.6.1. These are versions in the available `drd2-vina-py312`
environment, not a recovered package manifest from every historical docking
run; see [`docs/reproducibility.md`](../docs/reproducibility.md). On Windows,
use a Linux kernel in WSL 2; Linux and macOS kernels are also accepted. From
the repository root, create and register an environment with:

```bash
conda create -n drd2-vina-py312 -c conda-forge python=3.12.15 meeko=0.8.0 vina=1.2.7 rdkit=2026.03.1 biopython=1.88 pdbfixer=1.12 openmm=8.6.1 pandas=3.0.6 matplotlib=3.11.2 scipy=1.18.1 jupyter=1.1.1 ipykernel=7.4.0
conda activate drd2-vina-py312
python -m ipykernel install --user --name drd2-vina-py312 --display-name "Python (drd2-vina-py312)"
```

Select the `Python (drd2-vina-py312)` kernel in VS Code and run
`src/06_docking.ipynb`. Batch docking reads
`results/tables/scaffold_zinc22_predicted_pIC50.csv` and
`results/tables/random_zinc22_predicted_pIC50.csv`, generated by
`src/05_pIC50prediction.ipynb`.

## Outputs

- Prepared shared receptor cache: `docking/prepared/6CM4_Na/`.
- Single-ligand run files: `docking/runs/<ligand-file-stem>/`.
- Batch files and poses: `docking/runs/batch_top100_scaffold/` and
  `docking/runs/batch_top100_random/`.
- Successfully scored compounds:
  `results/tables/top100_docking_results_scaffold.csv` and
  `results/tables/top100_docking_results_random.csv`.
- Comparison-compound poses and scores: `docking/runs/comparison_smiles/` and
  `results/tables/comparison_docking_results.csv`.
- Model-versus-docking plots:
  `results/figures/ml_vs_docking_scaffold.png` and
  `results/figures/ml_vs_docking_random.png`.

Batch result tables contain compounds with a successfully parsed Vina score.
Preparation errors that raise `ValueError` or
`CalledProcessError` are printed and skipped; unexpected errors may stop a
batch. The scores are prioritization signals only. Compare ranks, inspect
poses, and validate the protocol against suitable reference ligands before
using docking results to guide experimental decisions.
